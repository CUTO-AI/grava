## Was gemacht wurde (mit Stolpersteinen)

### 1. Valhalla EU + NA
Auf dem Server neu gebaut (statt ~150 GB Tiles hochzuladen), sequenziell wegen
RAM. `/usr/local/bin/grava-valhalla-build.sh`, Log `/var/log/valhalla-build.log`.
Ergebnis: EU-Volume 101,7 GB, NA-Volume 66,6 GB, beide `/status`=200, Bike-Route
verifiziert. **Gotcha:** Das Log schrieb noch „NA baut noch…", obwohl der Build
längst fertig war (Container antwortete bereits) — im Zweifel `docker logs` +
`/status` prüfen, nicht nur das Build-Log.

### 2. DB-Import  ⚠️ Dump war defekt
Dump `000_CUTOVER/dbs15801946.sql` (Hosting-Panel-Export) ist **defekt**:
`CREATE TABLE` bricht nach der ersten Geometrie-Spalte ab (fehlende Spalten),
separate `ALTER TABLE … ADD PRIMARY KEY` scheitern am schon vorhandenen Schema.
**Die INSERTs sind aber vollständig.** Lösung:
1. Korrektes Schema aus Server-Backup laden (`/root/gravelexplorer.empty-preimport.sql`).
2. Alle Tabellen `TRUNCATE` (FK-Checks aus).
3. Aus dem Dump nur die Daten laden — CREATE-/ALTER-Blöcke via awk strippen,
   dann mit `SET FOREIGN_KEY_CHECKS=0` importieren.

Ergebnis: 7 users, 82 routes, game_region 186.840, game_edge 9.623,
game_edge_pass 18.086, oauth_connections 3, migrations 49.

### 3. .env-Merge + APP_KEY  ⚠️ kritisch
Server-`.env` als Basis, echte Prod-Secrets aus `000_CUTOVER/.env` übernommen:
**originaler `APP_KEY`** (entschlüsselt die Strava-Tokens in `oauth_connections` —
mit neuem Key wären alle Strava-Verbindungen tot), STRAVA_CLIENT_ID/SECRET,
MAIL-SMTP, APNS (KEY_ID `V7G328W57C`, `.p8` → `/var/www/app/storage/keys/`),
IOS_APP_ID, ADMIN_EMAILS, INTERNAL_TOKEN. **`DB_*`/`VALHALLA_*` blieben Server-
Werte.** Verifiziert per Decrypt-Probe: alle 3 Strava-Tokens entschlüsseln sauber.

### 4. DNS + HTTPS
DNS A für `cyberride.world`, `www.`, `admin.` → Server. `/etc/caddy/Caddyfile.cyberride`
aktiviert (ersetzt Default-Config), Caddy holt LE-Zerts automatisch. Verifiziert:
`/healthz`=200, `/api/v1/users/me`=401, `/api/v1/game/regions`=200 mit echten Daten.
`API_BASE_PATH=/api/v1`.

### 5. App-Crons
`/etc/cron.d/gravelexplorer` (User `www-data`, Logs `/var/log/gravelexplorer/`).
**Echte CLI-Namen** (Workbook-Namen `game:snapshot-daily`/`regions:*` existieren NICHT):
- `game:rush-tick` — minütlich
- `game:notify-dispatch` — alle 5 Min
- `cron:cleanup` — stündlich (baut Heatmap-Centroids gleich mit)
- `game:heal-crews` — stündlich (:17)
- `cron:heatmap-lines` — nächtlich 03:45
Aufruf-Muster: `php /var/www/app/public/index.php <cmd>`.

### 6. cell_key-Bug (gefixt, Commit 8ee4a38)
`cron:cleanup`/Heatmap scheiterte an `heatmap_cells.cell_key varchar(32)`
(„Data too long"): `CONCAT(blat,':',blon)` mit Float-Artefakten
(`48.150000000000006:…`, ~37 Zeichen). Fix: `CAST(… AS DECIMAL(9,6))` in
`HeatmapService::rebuild()` (Key ~19 Zeichen) + Migration `0050` (Spalte → VARCHAR(64)).

### 7. Storage-Dateien (Routen/Avatare)  ⚠️ NICHT im DB-Dump
Die Geometrie-Dateien liegen NICHT im DB-Dump. Vom alten Webspace per SFTP geholt
(siehe Runbook unten): routes 103/103 (User 1–4), avatars, crew-logos → nach
`/var/www/app/storage/`, Owner `www-data`. Danach matcht `cron:heatmap-lines` alle
Routen (vorher 0). **Gotcha:** Das FTP-Passwort enthält `$` — Creds-Datei MUSS
single-quoted sein, sonst expandiert die Shell beim Sourcen → „Login incorrect".

### 8. Strava-Portal + iOS
Strava-Portal-Callback (Client 260464) → `https://cyberride.world/auth/strava/callback`.
iOS `APIConfig.baseURL` → `https://cyberride.world/api/v1` (Deep-Link-Parser
host-agnostisch; Entitlements haben applinks für beide Domains).

### 9. Mail  ⚠️ netcup SMTP-Egress-Sperre
Absender `MAIL_FROM_ADDRESS` → `no-reply@cyberride.world` (passt zum Postfach
`cyberride-world-0001` @ udag). **Stolperstein:** netcup blockte ausgehende
SMTP-Ports (25/465/587) upstream (Timeout zu udag UND gmail; nicht ufw). Nach
netcup-Freischaltung: Test-Mail akzeptiert & zugestellt. **Kein Provider-Wechsel
nötig** — Versand läuft weiter über united-domains.

### 10. Notification-Backlog (Daten, kein Bug)
Nach dem ersten `notify-dispatch` kam „215 Deiner Reviere wurden übernommen".
Ursache: 645 `edge_taken`+1650 `pioneer_joined` aus einem Massen-Recompute auf
dem **alten** Server (2026-07-05 15:20) mit `notified_at=NULL` → als Digest
nachgeliefert. Einmalig (notified_at jetzt gesetzt). Restbacklog = 2008 `edge_new`
(Ledger-only, erzeugt keine Notification). Digest-Tap zeigte „Nicht verfügbar" →
iOS-Fix (`TerritoryDigestDestination` → Revier-Verlauf).

### 11. Surface-Check Valhalla-Detailpfad aktiviert
`SURFACE_CHECK_VALHALLA_ENABLED` auf Prod von `false` → **`true`** gesetzt
(php-fpm reload). Der Surface-Check nutzt damit den genaueren Valhalla-Map-

Server** (dort `false`). Fallback bei Problemen: wieder auf `false`. `/surface-check`
= 302 (Login-Redirect, Feature aktiv). Voller Test braucht authentifizierten GPX-Upload.

## Betriebs-Runbook

### Backend deployen
```
# lokal (Convanic-GitHub-Auth via gh, KEIN SSH-Key hinterlegt):
git add <files> && git commit -m "…"
git push https://github.com/Convanic/grava.git main
# auf Prod:
ssh -i ~/.ssh/grava_netcup root@159.195.200.131
cd /var/www/app && git pull --ff-only origin main
sudo -u www-data php public/index.php cli:migrate   # falls neue Migration
```

### DB-Zugriff
```
RP=$(cat /root/.grava_mysql_root)
docker exec grava-mysql mysql -uroot -p"$RP" gravelexplorer -e "…"
```

### Storage-Dateien vom alten Webspace nachziehen (SFTP)
Host `access-5000014930.ud-webspace.de`, User `a7729`, **SFTP Port 22**
(FTP/FTPS wird NICHT unterstützt). App liegt dort in `grava/`, Storage in
`grava/storage/{routes,avatars,crew-logos}`. Creds single-quoted ablegen!
```
lftp -c "set sftp:auto-confirm yes; open -u 'a7729,<PW>' sftp://access-5000014930.ud-webspace.de; \
  mirror --no-perms grava/storage/routes /var/www/app/storage/routes"
chown -R www-data:www-data /var/www/app/storage/{routes,avatars,crew-logos}
```

### Backups
- DB: `/usr/local/bin/grava-backup.sh` (mysqldump via docker, `--no-tablespaces`,
  14-Tage-Rotation) + nächtlicher root-cron 04:00.
- Vor-Import-Schema-Backup: `/root/gravelexplorer.empty-preimport.sql`.
